# v2.1.21

修复内网开发机重装、内网同步记录丢失后，外网镜像因序号重新从 #0001 开始而显示“已导入”、无法再次同步的问题。

## 变更

- 更新包清单新增可选的 `seriesId`（序号组标识）。外网据此区分“同一序号组中已导入的旧序号”和“重建后新的序号组”。旧版本生成的包和同步记录不含该字段，仍按原序号规则处理；旧版本读取新包时忽略该字段。
- 内网同步记录为空、且传输目录中仍有该项目的旧更新包时，导出设置提供“接续旧序号：从 #N+1 导出”。勾选后沿用旧序号组，外网按普通更新导入；不勾选则从 #1 开始新的序号组。
- 外网遇到新序号组的全量包时显示“新的序号组，需确认后导入”，列出引用变化，确认后才切换记录。核心层同样要求明确确认，不只在界面限制。
- 另一序号组的增量包一律拒绝；外网记录已有序号组后，遗留的无序号旧包不能被当作下一包导入。
- “导入下一包”不会自动推荐另一序号组的包。
- 导出恢复校验同步记录的序号和序号组与导出日志一致；接续候选必须同项目名、同基础分支且包文件存在，同一序号处存在不同序号组的包时拒绝接续；发布时拒绝同一仓库、序号组、序号的重复包。
- 保留包校验、仓库身份、原子引用事务、并发锁、推送确认、取消、冲突恢复及未提交修改保护。新增依赖 `uuid`（仅 `v4`）。

## 使用说明

- 接续时若外网镜像落后于传输目录中的最新包（如外网 #5、U 盘最新 #7），仍需按全量缺口确认。
- 从旧版本（无序号组）包接续时会生成新的序号组标识，外网镜像若记录的是其他标识，可能仍需确认序号组切换。
- 开始新序号组时，传输目录中不能已有同名的 #1 包文件，导出会以“包已存在”拒绝覆盖。

详见 README “内网同步记录丢失（如开发机重装）”。

## 验证范围

- 新增 Rust 回归（新序号组确认、另一序号组增量拒绝、接续、遗留无序号包、接续候选歧义/缺少包文件）及前端回归（新序号组行与确认流程、接续选项、扫描未完成时禁止导出）。
- 本地通过 `cargo test --locked`、`cargo fmt --check`、`cargo clippy -D warnings`、`tsc`、216 项前端测试、生产构建和版本一致性检查。
- 未进行 Windows / macOS 原生应用验收；同一序号并发发布的竞态没有确定性测试。自动化测试使用隔离的本地仓库。

## 安装包

- Windows 首次离线安装：选择 `with-webview2.exe`。
- Windows 已有 WebView2：选择 `no-webview2.exe`，亦用于应用内更新。
- macOS Intel / Apple Silicon：选择 `universal.dmg`。
- 最低 Git 版本为 **2.36**。
