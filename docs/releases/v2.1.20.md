# v2.1.20

修复 macOS 图形界面启动时找不到 Homebrew Git LFS，以及内网目标分支已检出时无法接收外网回传的问题。

## 修复

- macOS 的 Git 子进程保留原有 PATH 优先级，补充自定义 Git 所在目录、`/opt/homebrew/bin` 和 `/usr/local/bin`，使从 Finder / Dock 启动的应用也能使用已安装的 `git-lfs` 等辅助程序。不修改系统环境，不代为安装 Git LFS。
- Bundle 回传的同名分支正在当前工作树、linked worktree 或未完成操作中使用时，先保存到按包身份区分的 `review/…` 接收分支，保留原分支、索引、工作树和未提交修改。
- 接收结果提供“快进合入”操作，确认后才在已检出目标分支的工作树执行 `--ff-only --no-autostash`。工作区不干净、存在未完成操作或目标已分叉时明确拒绝，并保留回传以便后续处理。
- 独立接收分支沿接收记录检查并推送到原目标；未检出分支的直接更新、分叉备用分支及其原有推送规则保持不变。重复导入同一包不会覆盖之后的本地修改。
- 保留包校验、仓库身份、原子引用事务、并发锁、推送确认与 lease、取消、冲突恢复及删除分支的占用检查。未新增项目依赖。

## 验证范围

- 增加受限 GUI PATH 下的辅助程序查找测试，以及真实 Git LFS 的 clean / smudge 过滤器回归，覆盖默认 Git 和指定 Git 路径。
- 增加当前分支、linked worktree、未完成 Rebase、干净工作区、暂存与未暂存修改、未跟踪文件、分叉、重复导入及推送目标映射回归。
- 前端回归验证接收后不自动合入，取消确认不执行操作，确认后才调用快进命令。
- macOS 原生应用通过 LaunchServices 在仅含系统目录的 PATH 下启动，实测当前分支接收不改变 HEAD、取消确认不合入、未跟踪文件阻止合入，以及清理后显式快进时真实 LFS 文件正确检出。验证使用独立应用配置及临时仓库。
- 本地通过 114 项 Rust 测试、211 项前端测试和 15 项发布脚本测试，以及生产构建、版本一致性、fmt 和 Clippy；Windows / macOS CI 通过后构建安装包，并校验上传文件的下载 SHA-256。
- 未进行 Windows 原生交互、生产 GitLab 认证和生产仓库推送验收；自动化测试使用隔离的本地仓库。

## 安装包

- Windows 首次离线安装：选择 `with-webview2.exe`。
- Windows 已有 WebView2：选择 `no-webview2.exe`，亦用于应用内更新。
- macOS Intel / Apple Silicon：选择 `universal.dmg`。
- 最低 Git 版本为 **2.36**。
