## 本次调整：本地分支接收与独立管理页签

- Bundle 导入优先使用外网原分支名；同名分支可快进时更新，分叉时导入为 `<原名>-import-<序号>` 并提示实际名称。导入不创建审查分支，不自动 fetch、rebase 或切换当前分支。
- 本地分支、inbox 和接收记录在同一引用事务中保存。目标被主工作树、linked worktree 或进行中操作占用时拒绝更新；事务持有 HEAD 锁并复查，防止并发切换。重复包复用记录，不覆盖后续本地提交或用户修改的基准。
- 新记录区分普通分支接收，多个包可更新同一本地分支。普通分支按本地同名推送；旧版审查记录、目标映射和恢复流程继续兼容。
- 内网页签为“导出更新 / 导入回传 / 分支管理”；外网为“同步更新 / 回传提交 / 分支管理”。内网导入结果显示本地名称，可跳转管理页；外网管理选择与回传选择独立。
- 验证：166 项前端测试和 87 项 Rust 测试通过；分叉备用名提示补充后，定向回归通过。TypeScript、生产构建、Rust 格式、Clippy（`--all-targets -- -D warnings`）与差异空白检查通过。
- 使用模拟 Tauri IPC 在真实 Chromium 中检查内网深色桌面及 390px 窄窗口、外网浅色 768px 窗口；三个页签可操作，页面无横向溢出，宽分支表在自身容器内滚动。此项为浏览器界面验证，不代表原生桌面端验收。

- 后续已完成真实 macOS Tauri 往返、保护性操作和重启恢复测试，结果见[原生应用完整验证](./native-verification-2026-10-20.md)。

## 已实现

- 内网：导出更新 / 导入回传；外网：同步更新 / 回传提交。项目在顶栏切换，配置在弹窗编辑，选项、管理和日志默认收起。
- 浅色使用真实 WebGL fbm 渐变与明亮内容面板，深色使用夜景玻璃与香槟金强调。浅色、深色、跟随系统三种选择均保留；减少动态效果、不可用回退及渲染暂停由背景组件处理。
- `sync_updates` 在一个可取消的后端操作内导入镜像、逐个获取开发仓库引用或创建首次工作副本；取消后不启动后续仓库。
- `dev_sync_status` 比较实际引用和 origin 绑定，读取失败明确显示，不能当作新仓库或已同步。
- Bundle 回传以内容识别身份，原子提交 inbox、receipt 与 review 引用，在已配置的内网工作仓库中切换到专用审查分支整理，不再新建工作树。同包改路径、整理后重导、冲突继续均复用接收记录。
- 推送计划绑定源 OID、最终地址、目标引用及远程旧值。全部推送使用显式 lease；非快进仍需确认。查询和实际写入使用同一冻结地址，避免 URL 重写到其他仓库。
- 推送后核验远程结果；无法确认时显示未知。已核实推送的当前审查提交持久标记，后续生成新提交时自动重新成为待处理事项。
- 共享导出恢复只提交所属游标，不能把新的镜像接收状态倒退。导入前优先处理或阻止未完成导出。

## 本次审查修复验证

- 内网 Bundle 和 Patch 导入使用已配置的工作仓库，不创建 worktree；测试覆盖多分支顺序整理、冲突停止与继续、重复接收及未提交修改保护。
- 新增真实 Git 回归覆盖：Patch 合并提交拒绝导出、冻结导出范围、删除分支的原子旧值校验、rebase 期间分支保护、SHA-1/SHA-256 包导入、特殊工作树路径、未跟踪文件，以及 Patch 接收记录和收尾恢复。
- Patch 外部恢复按邮件数量核对新增提交，并检查工作区状态；多封邮件只应用部分后执行 `git am --quit` 或 `--skip`，不会被标记为整包已接收。旧恢复记录缺少数量时保留待处理状态。
- 删除分支通过 Git 引用事务锁住现有工作树的 HEAD，持锁复查占用后按旧 OID 删除；覆盖主工作树、linked worktree、bisect、rebase、files/reftable，以及取消后的锁释放。
- 空目录或无效 Patch 条目只影响自身：后端返回单包错误，界面显示“包内容异常”并禁用该包导入，其他回传包正常展示。
- 更新模块覆盖安装成功但重启失败后的重试、安装失败重试和并发调用保护；前端通知测试改为等待实际异步通知出现。
- `pnpm test`：163 项前端测试、15 项发布脚本测试通过。`cargo test --locked`：82 项 Rust 全量测试通过；本轮修复及组件统一新增 7 项 Rust 回归和 4 项前端回归。
- v2.1.7 的日期／日志时间、分页、空状态、表单错误摘要、表单分组、代码文本和提交差异刻度条使用 HeroUI。真实浏览器中检查了深浅主题与分页切换，确认时间字段不会进入 Tab 顺序；检查范围为组件验证页，不计作原生桌面端验收。
- `pnpm build`、`pnpm check:version`、Rust 格式检查、Clippy（`--all-targets -- -D warnings`）及 `git diff --check` 通过。
- v2.1.7 的 Windows CI 在两处 Patch 文件内容断言中因 CRLF/LF 差异失败，未构建安装包或公开 Release。测试夹具现固定 `core.autocrlf=false`、`core.eol=lf`；使用全局 `autocrlf=true` / `eol=crlf` 在本地复现原失败后，8 项 Patch 回归全部通过。产品的换行策略保持不变，后续发布版本为 v2.1.8。
- v2.1.8 的 Windows Rust 测试全部通过，Clippy 因一个只在 Unix 测试中使用的宏被全局导入而失败，未公开 Release。该导入已移入对应的条件编译测试；CI 调整为先 Clippy、再执行 Rust 测试，保留全部检查。后续发布版本为 v2.1.9。
- 当前最低 Git 版本为 2.36，以支持 NUL 分隔的工作树列表。当前已通过 macOS 和 Windows 的 Rust 测试；本轮尚未重新执行原生桌面交互或真实更新安装验证。

## macOS 桌面实测

以下为此前独立工作树流程的历史实测；本次改为在现有工作仓库导入后的验证见新增回归测试，不将历史结果视为当前桌面实测。

以独立应用标识和临时 Git 仓库运行 `pnpm tauri dev --config <验证配置>`，使用实际桌面按钮及 Tauri IPC 完成：

1. 内网导出 `verification-out-0001-full.bundle`。
2. 切到外网，一次点击完成镜像导入与开发仓库创建；开发仓库 origin 指向本地镜像，HEAD 为 main。

5. 应用展示冻结计划，确认后推送至临时裸远程的 `feature/ui-validation`。远程、导出分支和 pushed 标记均为 `bdd5768474e62aa228869f94506e3bec152a67d3`。
6. 已推送条目从默认待处理列表移除。实际查看深色主界面、菜单与确认弹窗，以及浅色着色器界面。
