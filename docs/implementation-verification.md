# 本轮实现与验证

正式应用采用单窗口双页签与 GitHub 风格深浅主题，并实现日常组合操作所需的后端能力。早期独立 HTML 原型和过时截图已移除，以[界面规范](./ui-design.md)及生产组件为准。下文保留已完成的分阶段验证记录。

## 已实现

- 内网：导出更新 / 导入回传；外网：同步更新 / 回传提交。项目在顶栏切换，配置在弹窗编辑，选项、管理和日志默认收起。
- GitHub 风格的纯色背景、灰色边框、蓝色链接/焦点与绿色主要操作。保留浅色、深色、跟随系统三种选择；已移除 WebGL、背景噪点、玻璃模糊与按钮缩放动效。
- `sync_updates` 在一个可取消的后端操作内导入镜像、逐个获取开发仓库引用或创建首次工作副本；取消后不启动后续仓库。
- `dev_sync_status` 比较实际引用和 origin 绑定，读取失败明确显示，不能当作新仓库或已同步。
- Bundle 回传以内容识别身份，原子提交 inbox、receipt 与 review 引用，使用独立工作树整理。同包改路径、整理后重导、冲突继续均复用接收记录。
- 推送计划绑定源 OID、最终地址、目标引用及远程旧值。全部推送使用显式 lease；非快进仍需确认。查询和实际写入使用同一冻结地址，避免 URL 重写到其他仓库。
- 推送后核验远程结果；无法确认时显示未知。已核实推送的当前审查提交持久标记，后续生成新提交时自动重新成为待处理事项。
- 文件锁失败区分实际占用与 I/O 错误，保留系统错误码；对远程桌面重定向路径提供本地导出后复制的操作说明。尚未验证现场 RDP 客户端的锁兼容性，不跳过文件锁。
- 共享导出恢复只提交所属游标，不能把新的镜像接收状态倒退。导入前优先处理或阻止未完成导出。

## GitHub 主题浏览器验收（v2.1.2）

在独立 Chromium 与模拟 Tauri IPC 中完成 28 个场景：浅色 / 深色，内网 / 外网，默认页、三个尺寸下的回传页、设置、项目表单和日志。窗口尺寸包含 1280×800、900×600 和 560×700。检查了实际截图与计算样式，主背景分别为 `#ffffff` / `#0d1117`，主要操作为绿色，无 canvas 和外层窗口阴影，主要容器无横向溢出。

原生控件、36px macOS 拖拽区域和白底黑色标志保留。验证没有调用真实导入、导出或保存配置。此次主题视觉检查使用 Chromium，未将它等同于 Windows WebView2 或 macOS WKWebView 的现场验收。

文件锁测试覆盖占用与 I/O 错误的区分、系统错误码保留、两种 tsclient UNC 表达、实际互斥和释放；现场 RDP 客户端的文件锁支持仍需其具体系统错误进一步诊断。

## macOS 桌面实测（早期流程验收）

以独立应用标识和临时 Git 仓库运行 `pnpm tauri dev --config <验证配置>`，使用实际桌面按钮及 Tauri IPC 完成：

1. 内网导出 `verification-out-0001-full.bundle`。
2. 切到外网，一次点击完成镜像导入与开发仓库创建；开发仓库 origin 指向本地镜像，HEAD 为 main。
3. 在临时开发仓库创建 `feature/ui-validation` 并提交，应用导出 `verification-back-0001.bundle`。
4. 切回内网，一次点击接收并在托管 worktree 整理。核对主工作区仍在原来的 main，inbox、receipt 和 ready 引用均存在。
5. 应用展示冻结计划，确认后推送至临时裸远程的 `feature/ui-validation`。远程、导出分支和 pushed 标记均为 `bdd5768474e62aa228869f94506e3bec152a67d3`。
6. 已推送条目从默认待处理列表移除。实际查看深色主界面、菜单与确认弹窗，以及浅色着色器界面。

验证配置使用独立标识 `com.jxwu.gitofflinesync.verify4e3a4293`，开发服务端口 1430。验证结束后关闭隔离实例，并曾启动使用原有配置的正常开发版（端口 1420）供检查；这些进程后来已退出。上述原生桌面验证仅在 macOS 完成；Windows 需要对应平台 CI 和桌面复验。

## 回传列表与窗口状态补充验证

- 使用隔离浏览器和 300 个模拟回传包，在浅色、深色下分别检查 1280×800、900×600、560×700。每页仅渲染 20 项，只有一个选中包导入入口；主要容器没有横向溢出。
- 自动测试覆盖分页、跨页搜索、状态筛选、接收后移除当前项、缺失或跨项目包不能导入，以及旧异步响应不能覆盖新目录。
- 使用独立应用标识启动真实 Tauri 实例：无历史状态时测得内容区 900×600；通过原生窗口 API 调整为 1100×700、位置 (100, 50)，正常关闭后验证状态文件写入；再次启动恢复了完全相同的逻辑尺寸和位置。
- 原生窗口验证通过窗口 API 自动执行，未把它当作人工鼠标拖拽验证。窗口几何单测还覆盖有效的 95% 屏幕尺寸、真正超屏、系统边框换算和异常零尺寸。
